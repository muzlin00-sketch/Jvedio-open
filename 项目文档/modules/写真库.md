# 写真库（图片图集）方案

> 目标：把 `E:\Pictures\plmm` 这类图包目录变成可浏览的写真库——**一个文件夹 = 一张卡片（一个系列）**，
> 封面用该文件夹的首张图片，点开可浏览整个图集。

## 一、现状盘点（先说结论：数据层已经有了，缺的是界面）

| 能力 | 现状 | 位置 |
|---|---|---|
| 数据类型 | 已有 `DataType.Picture` | `Core\Enums\DataType.cs` |
| 表结构 | 已有 `metadata_picture`（`PID`、`DataID`、`PicCount`、`PicPaths`、`VideoPaths`、`Path`、`Size`、`Hash`…） | `Core\ORM\Sqlite.cs` |
| 实体/映射 | `Picture : MetaData` + `PictureMapper` | `Entity\Data\Picture.cs`、`Mapper\Common\PictureMapper.cs` |
| 扫描 | `PictureScan`：一个 `ScanPath` 一条记录，`Title=文件夹名`、`PicCount`、`PicPaths=文件名列表`、`Size=图片总大小`、`Hash` | `Core\Scan\PictureScan.cs` |
| 扫描工厂 | `ScanFactory.CreatePictureScanner` 已接好 | `Core\Scan\ScanFactory.cs` |
| 侧边栏 | `PictureSideMenu` 存在，`Window_Main` 切到 `DataType.Picture` 时会换上 | `Core\UserControls\PictureSideMenu.xaml` |
| 看图 | `Window_ImageViewer`（单张大图 + 缩放） | `Windows\Window_ImageViewer.xaml` |
| 缩略图缓存 | `ImageCache` | `Core\Media\ImageCache.cs` |
| 自然排序 | `FileHelper.CustomSort`（`x|X|x2|x10`） | `Common\FileHelper.cs` |

**缺口**（这也是为什么现在"看不到写真"）：

1. **没有入口**：启动时只创建视频扫描任务（`WindowStartUp.xaml.cs:610` `new ScanTask(..., VIDEO_EXTENSIONS_LIST)`），
   `PictureScan` 只有工厂方法，全项目没有 UI 调用点。
2. **没有列表控件**：`TabItemManager` 只实例化 `VideoList`；`VieModel_VideoList` 的查询写死
   `.Eq("metadata.DataType", 0)`（视频），所以切到 Picture 模式只有左侧菜单变了，主区仍是视频列表。
3. **没有图集详情页**：只有单图查看器，没有"一个系列的缩略图墙"。
4. **没有封面规则**：`Picture` 只有 `PicPaths`（文件名列表），没有"封面"字段。

## 二、方案选型

### 选 A：独立窗口「写真库」（推荐）

新增 `Window_PictureLibrary`，不碰主界面的视频列表/标签页管线。

- 优点：`VideoList`/`VieModel_VideoList`/`TabItemManager` 零改动，风险最低；写真库与影片库数据本来就在不同表、不同 `AppDatabase` 记录里。
- 缺点：多一个窗口；与影片库的"同屏切换"体验略弱。
- 与现有代码契合度最高：扫描、表、实体、看图器、缩略图缓存全都能直接复用。

### 选 B：主界面加「写真」标签页

在 `TabItemManager` 里加 `TabType.GeoPicture`，复用 `VideoList` 的数据管线（把 `Picture` 适配成 `Video` 显示）。

- 优点：体验统一，切换快。
- 缺点：`VideoList`/`VieModel_VideoList` 里视频字段耦合很重（`ImageUrls`、`PlayCount`、`Series`、`Subtitles`…），
  适配层会产生一堆空字段；`TabItemManager` 是主界面最复杂的部分，改动面大、回归风险高。

**结论：选 A。** 后续如果体验需要，再把 A 的列表控件嵌进主界面（控件可复用，不算返工）。

## 三、数据与扫描设计

### 3.1 一个文件夹 = 一张卡片

`PictureScan` 现在的语义是"一个 `ScanPath` 一条记录"（`pathDict[path] = TryGetAllFiles(path)` 递归收集）。
直接扫 `E:\Pictures\plmm` 会变成**一整张卡片**，不符合需求。

两种落地方式：

1. **UI 层分组**（推荐，不改扫描核心）：扫描前枚举根目录下的一级子目录，每个子目录作为独立的 `ScanPath`
   传给 `PictureScan`。这样 `E:\Pictures\plmm\影子喵ghost - 胜利女神布兰儿\` 就是一张卡，
   子目录里再嵌套的子文件夹也归入同一张卡（`TryGetAllFiles` 是递归的）。
2. 改 `PictureScan` 内部按目录分组：逻辑更内聚，但会动到已对拍过的扫描代码，风险高。

选 1。

### 3.2 字段映射

| 卡片显示 | 数据来源 |
|---|---|
| 标题 | `Title`（= 文件夹名，原样保留 `Coser@`、`〖〗`、`–` 等字符） |
| 封面 | `PicPaths` 按自然序排序后的**第一个文件名**，`Path.Combine(Path, 文件名)` |
| 图片数 | `PicCount` |
| 视频数 | `VideoPaths` 按分隔符切分后的条数（可空） |
| 大小 | `Size`（`FileHelper.ToProperFileSize`） |
| 修改时间 | 目录 `LastWriteTime`，或 `LastScanDate` |

封面规则细节：

- `PicPaths` 存的是**文件名**（`PictureScan.cs:50` `Path.GetFileName`），拼 `Path` 才得到完整路径；
- 排序用 `FileHelper.CustomSort`，避免 `10.jpg` 排在 `2.jpg` 前面；
- 首图缺失/损坏 → 依次取第二张；全失败用占位图，不要让卡片空着；
- `gif` 也可以当封面（`ImageCache` 走 WPF 解码，取第一帧）。

### 3.3 扫描行为

- 扫描根：用户在窗口里选目录（记住上次选择，存 `Settings` 或 `AppConfig`）。
- 去重：`PictureScan` 已有按 `Path` 匹配已有记录的逻辑（`PictureScan.cs:108-160`），重复扫描只更新
  `PicCount`/`PicPaths`/`VideoPaths`，不会重复建卡。
- 增量：新增子目录会新建卡；目录被删的记录先不自动清理（后续可加"清理失效卡片"按钮）。
- 每个文件夹一条 `metadata` + 一条 `metadata_picture`（`PictureScan` 已处理双表写入，实施时确认一遍）。

## 四、界面设计

### 4.1 `Window_PictureLibrary`

```
┌───────────────────────────────────────────────────────┐
│ [库: 写真库 ▾]  [扫描目录…]  [搜索____]  [刷新]        │
├───────────────────────────────────────────────────────┤
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐          │
│  │ 封面   │ │ 封面   │ │ 封面   │ │ 封面   │          │
│  │ 标题   │ │ 标题   │ │ 标题   │ │ 标题   │          │
│  │83P 1V  │ │52P 1V  │ │ 42P    │ │ …      │          │
│  └────────┘ └────────┘ └────────┘ └────────┘          │
└───────────────────────────────────────────────────────┘
```

- 卡片：封面图 + 标题（两行截断）+ `N P`/`N V` 角标 + 大小；
- 网格自适应列宽（按窗口宽度算列数，参照 `VideoList` 的 `GlobalImageWidth` 思路）；
- 用 `ListBox + VirtualizingStackPanel`，几千张卡也不卡；
- 双击卡片 → `Window_PictureDetail`；右键菜单：打开文件夹、重新扫描、从库中移除。

### 4.2 `Window_PictureDetail`

- 顶部：标题、图片数、视频数、总大小、路径（可复制）；
- 主体：缩略图墙（`ImageCache` 小图，懒加载）；
- 单击缩略图 → 大图预览（复用 `Window_ImageViewer`）；
- 键盘 `←/→` 翻页、`Esc` 关闭、`Enter` 用系统看图器打开；
- 有视频时列表里显示视频条目，双击用系统默认播放器打开。

### 4.3 入口

- `Window_Main` 菜单加「写真库」一项（或 `PictureSideMenu` 里加"打开写真库"按钮），`Show()` 非模态；
- 首次打开时若没有 `DataType=Picture` 的 `AppDatabase` 记录，自动建一个（名字"写真库"），
  避免用户还要先去"数据库管理"里手工建库。

## 六、验收标准

拿用户给的 24 个目录做验收：

1. 扫描 `E:\Pictures\plmm` 后卡片数 = 24（每个一级子目录一张）；
2. 每张卡封面 = 该目录自然序第一张图；
3. `PicCount` 与目录内图片数一致；`[83P-1V-1.44G]` 这类标题原样显示，不被截断成乱码；
4. 双击进入详情，缩略图数量 = 图片数，大图可翻页；
5. 重复扫描不重复建卡；删掉目录后再扫描，旧卡不崩（可后续加清理）；
6. 中文、`@`、`〖〗`、空格、`–`（U+2013）路径全部能读；
7. 2000+ 张图滚动不卡（虚拟化生效）。

## 七、风险与取舍

- **缩略图内存**：`ImageCache` 有容量上限，卡片只加载可见项；大图用 `BitmapCacheOption.OnLoad` 立即释放文件句柄，避免"图片被占用无法删除"。
- **首图解码失败**：损坏图/非图片扩展名（如 `Thumbs.db`）要过滤，否则整个卡片封面空白。
- **文件夹命名极不规则**（用户样本里就有 `Coser@`、`〖〗`、`_–_`、`“42_photos_and_11_video”`）：标题一律原样显示，不做"智能清洗"，避免把 Coser 名拆错；后续可加"按 Coser 聚合"（解析 `Coser@xxx` / `xxx_` 前缀），但那是二期。
- **视频文件**：文件夹里的 mp4 只记入 `VideoPaths`，不生成缩略图（FFmpeg 抽帧成本高），详情页显示条目即可。
- **不做刮削**：写真库不参与番号识别/网络刮削，`VID` 留空，避免污染影片库的匹配逻辑。
