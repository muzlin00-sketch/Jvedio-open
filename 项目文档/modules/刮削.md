# 刮削

两条完全独立的刮削链路，**先内置、后插件**，谁先出结果用谁。用户侧怎么配见
[刮削与插件](../刮削与插件.md)；本文讲实现、改哪里、加源怎么加。

## 链路总览

```
VideoDownLoader.GetInfo()
├─ 1. BuiltinCrawlerManager.GetInfo()      ← 内置（源码）：豆瓣 / TMDB / Bangumi
│     命中即返回，不进插件链路
└─ 2. GetCrawlerServer() → PluginInvoker   ← 插件（DLL）：bus / db / library / fc2
      按插件顺序、按源顺序，第一个返回有效字典即返回
```

顺序在 `Core/Net/VideoDownLoader.cs` 的 `GetInfo()` 里写死：内置先跑，`builtin != null` 直接 return。
这么排的原因：番号插件在没装时会抛 `CrawlerNotFoundException`，而普通影片不该依赖它。

## 内置刮削器

| 文件 | 作用 |
|---|---|
| `Core/Crawler/Builtin/IBuiltinCrawler.cs` | 契约：`Id` / `Name` / `IsEnabled` / `RequiresKey` / `GetInfo` |
| `Core/Crawler/Builtin/BuiltinCrawlerManager.cs` | 注册与路由：按顺序跑，命中即停，异常记日志换下一个 |
| `Core/Crawler/Builtin/BuiltinCrawlerQuery.cs` | 文件名解析结果（标题 / 年份 / 是否单集），一次解析多源复用 |
| `Core/Crawler/Builtin/BuiltinSupport.cs` | HTTP 封装：`CreateHeader` / `GetJson` / `Delay`，失败判定见下 |
| `DoubanCrawler.cs` / `TmdbCrawler.cs` / `BangumiCrawler.cs` | 三个源的具体实现 |

**返回值的唯一约定**：字典键名 = `Jvedio.Entity.Video` 的属性名，由 `Video.ParseDictInfo` 反射写入。
键名写错不会报错，只是静默不生效——加字段时对着实体属性名抄。
`Title` 必须有值，否则上层视为未命中。

**加一个内置源**：

1. 新建 `XxxCrawler.cs`，实现 `IBuiltinCrawler`；
2. 在 `BuiltinCrawlerManager.EnsureInitialized()` 里注册（顺序就是优先级）；
3. 在 `DownloadConfig` 加开关属性（`_EnableXxxCrawler`）并在设置页 `Window_Settings.xaml` 加勾选框；
4. 在 `Jvedio.csproj` 加 `<Compile Include>`。

`IsEnabled` 读 `ConfigManager.DownloadConfig`；`RequiresKey` 为 true 的源在没配 Key 时直接跳过，
不要让它抛异常。

**`HttpResult` 的坑**：`Success` 永远是 `false`（历史遗留），判断成败只能看
`Error != HttpResult.DEFAULT_ERROR_MSG`。`StatusCode` 默认值 403，别用它判断"没请求过"。

## 番号插件

| 文件 | 作用 |
|---|---|
| `Core/Plugins/Crawler/CrawlerManager.cs` | 启动时扫 `plugins/crawlers/<目录>/`，解析 `main.json`、加载 DLL、登记 `PluginMetaDatas` |
| `Core/Config/Common/ServerConfig.cs` | 每个插件的「源」记录（Url / Cookies / Enabled / Available），存数据库 `Servers` 配置项 |
| `Core/Net/VideoDownLoader.cs` | 按源逐个调用，`PluginInvoker.SetMethod("GetInfo")` 反射进 DLL |
| `Core/Crawler/CrawlerServer.cs` | 源的数据结构，`AttachToDict` 把 Url/Cookies 塞给插件 |

**加载三件事**，少一件插件就"装了但没用"（细节见 [踩坑约定](../踩坑约定.md) 第 33 条）：

1. 目录里有 `main.json` + DLL，目录名即 PluginID 后半段（`crawlers/bus` → `crawler/bus`）；
2. DLL 被复制到 `plugins/crawlers/` 顶层后加载（`Assembly.Load(bytes)`，避开 zone 标记）；
3. 数据库 `Servers` 里有 `PluginID` 匹配、`Enabled`、`Available == 1`、`Url` 非空的记录。
   全新安装时 `ServerConfig.Read()` 会补默认四条（JavBus 启用，其余关闭）。

**插件契约**（闭源 `CommonNet.dll`）：实现 `Jvedio.CommonNet.Crawler.AbstractCrawler`，
`GetInfo(header, dataInfo)` 返回同样的 `Dictionary<string, object>`。插件用 `BaseUrl`（来自源记录）
拼路径，所以换镜像站只改 Url，不用动 DLL。

## 怎么验证改动

```powershell
# 1. 编（改过 Core 内的文件要先编 Core）
cd Jvedio-WPF\Jvedio.Core ; dotnet build -c Debug
C:\Windows\Microsoft.NET\Framework\v4.0.30319\MSBuild.exe `
  Jvedio-WPF\Jvedio\Jvedio.csproj /t:Build /p:Configuration=Debug /v:m /nologo

# 2. 跑：用一个独立运行目录，别碰日常库
#    看日志 data\<用户名>\log\<日期>.log 里的刮削记录
```

验收标准：**普通影片刮到正确条目**、**番号类用自带插件刮出标题/演员/封面**、
**刮不到时日志里能看到换源过程而不是静默失败**。只看到"没报错"不算通过。
