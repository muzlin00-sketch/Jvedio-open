# 手机网页版

移动端单页应用，单文件 `Resources\Web\index.html`（无构建步骤，改完直接部署）。
服务端路由与数据在 `Core\Lan\LanServer.cs`。

## 页面结构

顶层是几个平级页面容器，用 `.show` 类切换，没有路由框架：

| 容器 | 作用 |
|---|---|
| `#grid` | 影片网格（首屏） |
| `#detailPage` | 详情页 |
| `#playerPage` | 播放页 |
| `#loginMask` | 登录遮罩 |

导航用 `history.pushState` / `replaceState` 维护，返回键由 `popstate` 监听决定"关哪一层"。
新增页面要同时处理：进入时压历史、关闭时回退、`popstate` 里的分支。

## 列表与分页

- 首页 30 条一页，滚动到底部触发加载（`setupInfiniteScroll`）。
- 请求带 `detailToken` / `playerToken` 做取消：快速切页时旧响应不许写进新 DOM。
- 搜索走 `/api/videos?keyword=`，服务端谓词覆盖标题、识别码与**文件路径**
  （短片没有识别码和标题，只能靠文件名搜，见[踩坑约定 #15](../踩坑约定.md)）。

## 图片

- 封面走 `/image/small/{id}`，详情大图走 `/image/big/{id}`，截图走 `/image/preview/{id}`。
- 一律 `img.loading = 'lazy'` + `img.decoding = 'async'`。
- 加载完成加 `.loaded` 类淡入；失败时退回小图，仍失败则隐藏整块，不留空白。
- 开了访问口令后，图片地址要拼 `?token=`（`<img src>` 带不了请求头）。

## 卡片点击

封面 → 播放；文字区 → 详情。判定用 `cover.contains(e.target)`，理由见[踩坑约定 #8](../踩坑约定.md)。

## 播放页控件与全屏

- 控件栏 `.vc` 默认 3.5s 后自动隐藏（`hideTimer`），单击视频切换显隐。
- 单击判定用 **`pointerdown` 时的状态快照**（`uiVisibleAtTap`），不看当前 DOM——
  移动浏览器 tap 后会补发 `mousemove`，直接读当前状态会"显示完立刻又隐藏"，
  详见[踩坑约定 #27](../踩坑约定.md)。
- 双击（300ms 内两下）左右半屏快进/快退，因此单击要延迟 300ms 才生效。
- 全屏用标准写法：`requestFullscreen` / `webkitRequestFullscreen`，都不支持时才退到
  `video.webkitEnterFullscreen()`（iOS 兜底）；`fullscreenchange` 只同步按钮图标。
  **不要**改成 CSS 伪全屏来"绕开原生全屏"——页面自带按钮本来是好的，
  手机浏览器自带的快捷全屏和自定义控件不兼容是浏览器层行为，页面改不了，见[踩坑约定 #28](../踩坑约定.md)。

## 随机列表与状态恢复

- 「随机推荐」不是一次性渲染：结果存在 `state.randomItems`，由 `renderRandomItems(items)` 统一渲染
  （标题栏 + 「换一批」 + 卡片），这样从播放页/详情页返回时能原样重建，而不是回到首页第一屏。
- 列表状态存 `sessionStorage['jvedio.listState']`：`mode`（list/random）、`dbId`、`keyword`、
  `view`、`randomItems`、`scrollY`。`bootApp()` 启动时若 `mode === 'random'`，直接重放随机列表并恢复滚动位置。
- 滚动位置用 400ms 节流的 `scroll` 监听写入，`loadPage()` 渲染完成后也会存一次。
- 注意：`sessionStorage` 是**按标签页**的，换标签页或新开窗口不会恢复，这是有意为之（避免多窗口互相覆盖）。

## 相似推荐

- 接口 `GET /api/similar/{id}?count=N`（1~30，默认 12），实现在 `LanServer.HandleSimilar`。
- 候选池由六路召回拼成：同演员（120）、同导演（60）、同系列（60）、同发行商（40）、
  文件名种子（每个 40，上限 400）、同目录（小文件夹才用，40），最后加 80 条随机样本兜底。
- 打分按内容形态切换权重：
  - 有演员或导演 → 演员 42%、导演 18%、剧情简介 15%、文件名 15%、同系列 5%、发行商 5%；
  - 只有文件名（短片）→ 文件名 66%、剧情 10%，其余各 4%~5%。
- 文件名相似度分两类：番号比字母前缀 + 数字接近度；中文标题比开头 2~3 字的系列标记 + 二元组 Dice。
- 随机只用于**排序阶段**对同档候选（0.03 一档）打散，不参与分数；低于 `SIMILAR_MIN_SCORE`（0.09）的
  结果直接丢弃，前端 `items` 为空时整块移除，宁可不显示也不塞无关内容。
- 改动这块必须同时验证三种源：有演员的番号、无演员只有番号的短片、中文系列短片。


## 改前端时注意

- 文件是一个整体，改之前先定位到具体函数；全局搜索函数名比按行号找可靠。
- 改完必须做 JS 语法检查（提取 `<script>` 内容后 `node --check`），再确认 `<div>` 开闭数量一致。
- 部署要同时更新 `Resources\Web\index.html` 和部署目录的 `Web\index.html`，
  并校验 SHA256——只复制 exe 不会更新内嵌页面。
- 验证要在移动视口（390×844 之类）实际点击，不能只看 DOM。

## 已知限制

- 浏览器不支持的格式（如 `.wmv`、`.avi`）无法播放，需要服务端转码——当前未实现。
- 无缓存层，重复进入同一列表会重新请求。
