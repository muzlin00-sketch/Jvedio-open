# 投屏

把影片推给局域网内的 DLNA 渲染设备（投影仪、电视）。
代码：`Core\Lan\Dlna.cs`（发现与控制）、`Core\Lan\LanServer.cs`（`/api/cast/*`）、
`index.html`（设备面板与远程控制）。

## 工作方式

服务端推送，不由手机播放：

```
手机 ──POST /api/cast/play/{dataId}?device=名称──> 服务端
                                                    │
                                      SetAVTransportURI(mediaUrl)
                                                    │
投影仪 ──GET http://<同网段本机IP>:5200/stream/{id}──┘   (HTTP Range 拉流)
```

手机端变成一个遥控器：拖进度条、暂停、快退都通过 `/api/cast/*` 代理到设备。

## 发现

`DlnaCaster.Discover()` 发 SSDP M-SEARCH（UDP 1900），三种 ST 都搜
（`MediaRenderer:1`、`MediaServer:1`、`ssdp:all`），每个本机 IPv4 一个 socket，
按 `Location` 去重，再过滤掉没有 `AVTransport` 服务的设备。

结果缓存在 `_castDevices` / `_castDevicesAt`，`/api/cast/devices?refresh=1` 强制重扫。
实测客厅环境约 2.3 秒发现 5 个渲染器。

## 关键约束

**流地址必须用与设备同网段的本机 IP。** 用 `GetLocalIpFor(设备IP)` 做子网匹配，
不能用自动选出的地址——装了 VPN 时会挑到虚拟网卡，投影仪拉不到流，
状态卡在 `TRANSITIONING`、进度恒为 `00:00:00`（[踩坑约定 #3](../踩坑约定.md)）。

**进度要查 `GetPositionInfo`。** `RelTime` 属于它，不在 `GetTransportInfo` 里
（[踩坑约定 #4](../踩坑约定.md)）。

**`seek` 只支持绝对时间**（`REL_TIME`）。前端做增减量时自己算好目标秒数再发。

**`stop` 要幂等。** 未在投屏时也返回成功，否则前端 `.catch` 会让界面卡在投屏态
（[踩坑约定 #5](../踩坑约定.md)）。

## 前端交互

进投屏后**播放页保留**，视频区被远程面板替换：设备名、连接状态、进度条、播放/暂停/停止、
「停止投屏」出口。这是成熟站点的通行做法——用户不离开播放上下文。

进度条拖动要区分本地与远程：投屏态下拖动只算目标时间并调 `castSeekTo`，
松手才发一次 seek，拖动中轮询要 `if (dragging) return;` 跳过，避免自己覆盖自己。

进入投屏前必须先关详情页并解锁滚动（[踩坑约定 #12](../踩坑约定.md)）。

## 鉴权

开启访问口令后，投影仪拉流带不了 Cookie，所以投屏时签发绑定 `dataId`、十分钟有效的
临时令牌拼在流地址上。校验顺序：投屏令牌 → 普通令牌 → 拒绝（[踩坑约定 #6](../踩坑约定.md)）。
详见[访问口令](访问口令.md)。

## 媒体兼容

实测投影仪支持 H.264 + AAC（抽样 20 个文件：h264 36 路、mpeg4 2 路、aac 19 路），
可直接播，无需转码。遇到不兼容格式当前没有转码路径，属于已知缺口。

## 排障顺序

1. 状态 `TRANSITIONING` 不动 → 先查流地址的 IP 是否与设备同网段。
2. 状态正常但进度 `00:00:00` → 查是否只调了 `GetTransportInfo`。
3. 退出后 UI 没恢复 → 查 `restoreLocal()` 是否在 `.then` 和 `.catch` 都执行。
4. 拖动后进度乱跳 → 查是否漏了 `dragging` 早退，或拖动监听没清理。
