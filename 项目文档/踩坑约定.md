# 跨模块陷阱

除下列代码级规则外，不在此重复部署、构建环境或功能实现。
按任务阅读：部署见 [部署.md](部署.md)，UI 见 [设计规范.md](设计规范.md)，功能见 [modules/](modules/)，构建环境与历史见 [MAINTAINING.md](../MAINTAINING.md)。

## 编号与引用规则

**编号是这条约定的身份，不是它在列表里的位置。**

- **只追加**：新条目写在文件末尾，编号取「当前最大号 + 1」。不插入中间、不重排、不复用已删除编号。
- **引用写法只有一种**：`踩坑约定 #N`。多条目连写用顿号，如 `踩坑约定 #2、#3`。
- **引用前确认编号存在**。悬空引用是最隐蔽的失效——读代码的人按图索骥会扑空。
- **改编号 = 改契约**。必须重编号时，同一次改动里把所有引用点一起改。
- 新增条目后检查：编号连续、引用可达。

## 构建与配置

1. **改 `Jvedio.Core` 内文件后必须先单独编译 Core**。`HttpProtocol.cs` 位于 `Jvedio\Core\Lan\`，但 `Jvedio.Core.csproj` 用 `<Compile Include="..\Jvedio\Core\Lan\HttpProtocol.cs" Link="..." />` 方式引用同一份源码，独立编译成 `Jvedio.Core.dll`。主项目引用的是那个 DLL，不是源码。只编主项目 → 主项目用的仍是旧 DLL，表现为「改了代码但行为完全不变」，且没有任何报错。顺序固定：先 `dotnet build` Core，再 MSBuild 主项目。强制重建主项目也**不能**解决——它本来就没有这文件。

2. **`AbstractConfig` 反射赋值对 `int` 等值类型会静默失败**。读取配置时 JSON 数字被反序列化成 `long`，`prop.SetValue(this, value, null)` 赋给 `int` 属性抛 `ArgumentException`，外层 `catch { continue; }` 吞掉。结果：这些配置项永远停留在构造函数默认值，日志无任何线索。已修为赋值前先 `Convert.ChangeType`。**症状特征**：改了配置、重启、行为没变；或「端口被占用」报错但该端口其实是空的（程序读到的仍是默认端口）。见到这类现象先确认属性真实类型。

## 局域网服务与投屏

3. **投屏流地址必须用与目标设备同网段的本机 IP**。`GetLocalIpAddress()` 会挑到第一块可用网卡，装了 VPN 时可能返回 `192.168.3.32/32` 之类，而投影仪在 `192.168.10.x` —— 投影仪拉不到流，状态卡在 `TRANSITIONING`、进度永远 `00:00:00`。必须用 `GetLocalIpFor(设备IP)` 做子网匹配。

4. **播放位置在 `GetPositionInfo`，不在 `GetTransportInfo`**。`RelTime` 属于前者；只调后者拿不到进度，表现为进度条恒为 `00:00:00`。

5. **投屏写接口要幂等**。`/api/cast/stop` 在未投屏时若返回 5xx，前端 `.catch` 会让界面卡在投屏态。后端应返回 `{ok:true, alreadyStopped:true}`，前端则让「恢复本地播放」在 `.then` 和 `.catch` 都执行。

6. **投屏需要临时凭证时要签短令牌，不能放开整个流接口**。投影仪拉流带不了 Cookie，若直接跳过校验，知道 DataID 就能下载整部片。做法是签发绑定 dataId、有效期十分钟的临时令牌拼在流地址上；校验顺序为投屏令牌 → 普通访问令牌 → 拒绝。

7. **自建 HTTP 服务不读请求体时，参数只能走查询串**。要传口令这类敏感值必须给 `HttpRequest` 补 `Body`（按 `Content-Length` 读、限制 64KB），否则口令会进 URL、访问日志和浏览器历史。

## 前端

8. **封面等大块点击区域用 `contains` 判定，不要靠 DOM 层级猜**。给子元素（`cover`）单独绑 `click` 只覆盖它自己的盒模型；图片未加载完（`<img>` 尺寸为 0）、圆角 `overflow:hidden` 裁角、亚像素取整，都会让点击漏到父容器，那里没监听 → 用户感知是「点了没反应」或「像刷新」。改为在整卡上监听，用 `cover.contains(e.target)` 判断归属。

9. **移动端快速连点会被判成双击缩放**。卡片这类可点区域要加 `touch-action: manipulation`（顺带去掉 300ms 延迟），并 `user-select:none`、`-webkit-touch-callout:none` 防长按选中与弹出保存菜单。否则用户连点两次页面会「跳一下」，同样像刷新。

10. **手势结束会紧接着触发 `click`**。滑动手势（如横滑快进）结束后必须用时间戳守卫（如 `lastEndAt` + 350ms 窗口）屏蔽紧随的 click，否则一次滑动会连带触发暂停/播放。

11. **flex 子项要滚动必须给 `min-height: 0`**。flex 子项默认 `min-height:auto`，`overflow-y:auto` 不生效，内容把容器撑开而不是内部滚动。

12. **层级要查清楚再改**。详情页 `z-index` 曾高于播放页，导致从详情页进投屏后远程面板被盖住。进入投屏/播放态前先关掉详情页并解锁滚动，必要时 `history.replaceState` 抹掉多余历史。

13. **`window` 上的拖动监听必须清理**。投屏进度条在 `window` 上绑 `pointermove/pointerup`，不清理会随每次进入投屏累积，造成重复 seek。用统一的 `cleanup` 函数在进入、退出、关闭播放页三处调用。

## 数据与查询

14. **多表 join 后必须给列加别名**。`metadata` 与 `metadata_video` 都有 `DataID` 等列，不带别名直接写会报 `ambiguous column name`。统一用 `m.DataID` / `v.DataID`。

15. **搜索条件要覆盖短片场景**。部分短片 `VID` 与 `Title` 都为空，唯一可检索文本是文件名。搜索谓词里要包含 `metadata.Path`，否则这类片搜不到，用户会以为搜索坏了。

## 工具与环境

16. **不要抢占前台焦点**。用户可能正在别的窗口工作，禁止 `SetForegroundWindow` 之类把应用拉到最前。

17. **`ffprobe` 可能不存在**，只有 `ffmpeg`。需要探测编码时解析 `ffmpeg -i` 的 stderr，不要假定 ffprobe 可用。

18. **静态文件服务要有扩展名白名单和 `..` 拦截**。自建服务容易漏这层，一旦漏了就等于把磁盘暴露给局域网。

## 资源与依赖

19. **判断「资源是否真的嵌进程序」要实际枚举，不能靠搜二进制**。`TryServeWebPage` 里"找不到磁盘 `Web\index.html` 就用内嵌资源"的回退分支曾长期是死代码：`index.html` 根本没写进 csproj，`GetManifestResourceStream` 永远返回 null。用 grep 在 exe 里搜资源名会命中——但那只是源码里的字符串字面量，不是资源本身。正确做法是 `Assembly.GetManifestResourceNames()` 枚举。已在 csproj 补 `<EmbeddedResource>` + 固定 `<LogicalName>`，并在 `/api/health` 暴露 `hasDisk` / `hasEmbedded` / `stale`，部署后可直接查。

20. **全盘扫描的递归能力原本完全来自闭源 `QueryEngine`**。同类方法的 `ScanTopPaths` 用的是 `SearchOption.TopDirectoryOnly`，只扫各盘根目录。移除 `QueryEngine` 时若只删调用，全盘扫描会静默退化成"只扫根目录"，不报错也没日志。替换实现必须自己做递归：逐目录 `try/catch`（`SearchOption.AllDirectories` 遇到第一个无权限目录就整趟抛异常）并跳过 `FileAttributes.ReparsePoint`（否则 junction 会成环或重复收集）。见 `ScanHelper.GetAllFilesRecursively`。

21. **闭源 `JvedioLib.dll` 的识别码分类依赖两张约 1.3 万字符的前缀表**（`Censored` / `Uncensored`），`GetVideoType` 据此返回 0 普通 / 1 无码 / 2 有码。这些是**数据不是逻辑**，已原样导出到 `Utils\Extern\IdentifyTables.cs`。替换逻辑前先确认表未过期，且必须用差分测试对比新旧输出——识别码错了不会报错，只会导致刮削到错误条目、与库中记录匹配不上。

22. **同一个设置有两个"真源"，其中一个永远不同步**。`ScanHelper` 曾有静态可写 `MinFileSize`（默认 0，从不与 `ConfigManager.ScanConfig.MinFileSize` 同步），而 `IsProperMovie()` 与 `FilterFiles()` 用的正是它。结果是用户在设置里配的最小文件大小在**这两条路径上永久失效**，且没有任何日志。已改为只读派生属性 `MinFileSizeBytes`（配置存 MB，属性换算成字节）。判据：出现 `public static ... { get; set; }` 且语义等同某个配置项时，先确认它是否被赋值过；没人赋值就是死真源。

23. **替换无源码的闭源组件，必须用真实数据做差分测试，不能靠读代码推断**。`Identify` 的替换就是这么定下来的：从用户库导出 2344 个真实文件名，先跑旧 DLL 存基线，再逐条对齐。过程中发现三条与实际直觉相反的规则：

    - `IsHDV` 是**纯子串**匹配，所以 `hhd800.com@…` 含 `hd` 也判为高清（按词边界匹配会让存量库判定整体漂移，故保持一致）。
    - `IsCHS` 认的是 `-C` / `_C` 后不接字母；`-C办公`、`_C.mp4` 算字幕，`- C`（带空格）不算。
    - `GetVideoType` 里**纯数字前缀判为无码**（`123456-789`），而非按厂牌表。

    最终一致率：`GetVideoType` 2344/2344、`IsCHS` 2344/2344、`IsHDV` 2343/2344、`GetVID` 98.8%。**未对齐的 1.2% 是刻意保留的**：旧实现会把哈希文件名（`0gwjnw0w3vmqyhw4ooipo`）和域名水印（`kcf9.com-00…`）截出 `GWJNW-0W`、`COM-00` 这种码，照抄只会让刮削去请求不存在的番号。新实现返回空。

    差分测试的成本远低于"改完让用户自己去发现刮错了"。

24. **闭源库里的"小类型"不一定能单独换掉——它可能就嵌在 API 签名里**。拆 `SuperUtils` 时本以为枚举（`StreamKind`、`IdType`、`InsertMode`）是最容易的先手，各 30/18/5 处、纯声明、零逻辑。实测全部编译失败：

    - `IdType` 是 `SuperUtils.Framework.ORM.Attributes` 里特性构造函数的参数类型（`[Table(IdType.AUTO)]`），换成本地枚举后特性就不接受；
    - `StreamKind` 是 `MediaInfo` / `MediaParse` 方法的入参；
    - `InsertMode` 是 ORM 插入方法的入参。

    结论：**枚举不是独立叶子，而是闭源库 API surface 的一部分**。只有把消费它的方法一起替换，枚举才能跟着走。替换顺序必须按"类型与 API 的耦合深度"排，不能按改名工作量排：

    1. 纯函数、参数全是基元类型 —— 已换：`DateHelper`、`ConstValues`、`JsonUtils`（共 107 处引用）；
    2. 自包含类（不接收、不返回库内其他类型）—— `ObservableString`、`HttpResult`、`RequestHeader`；
    3. 中间件（日志、任务基类）—— `AbstractLogger`、`AbstractTask`；
    4. ORM 整层（`Where`、特性、枚举、`Sqlite`）—— 必须一次性整体搬，中途混合状态编译不过。

    另记一条统计陷阱：按"类型名在源码中出现次数"排优先级会产生**假阳性**。`SuperUtils` 的 96 个公开类型里有 10 个（`Delay`、`JsonUtils`、`AbstractConfig`、`AppConfig`、`Sqlite`、`CrawlerHeader` 等）与本项目或已替换的本地类型同名，纯按名字统计会得出 42、24、11 这类虚高数字。真实依赖是 40 个类型；判断方法是先查源码里是否已存在同名 `class` / `enum` 定义，再统计引用。
25. **番号尾缀剥离是"白名单"不是"全剥"，且正则吃掉的字母要整段还原后再判断**。扫码入库走 `Identify.GetVID` = `NormalizeVID(GetRawVID(...))`：

    - `GetRawVID` 的标准形式正则 `([A-Z]{2,6})-([0-9]{2,5})([A-Z])?` 只允许把**一个**尾字母吃进识别码，这是为了保住 `HRV-030A`、`SSIS-123A` 这类本身带尾字母的合法番号；
    - 但 `ABC-123CH` 会先被匹配成 `ABC-123C`，剩下 `H` 单独留着。所以命中后要把"数字后连写的整段字母"（`C`+`H`）合起来查白名单，命中才整段丢弃，否则保留那个字母；
    - 白名单只有明确是来源/字幕/清晰度标记的：`C`、`CH`、`CHS`、`CHT`、`U`、`UC`、`HD`、`FHD`。`A`/`B` 故意不收——`HRV-030A` 与 `HRV-030` 是两个不同作品，早期"数字后尾字母全剥"的写法会把它误截成 `HRV-030`；
    - 改这里必须跑文件名矩阵（`ABC-123-ch` / `ABC-123ch` / `ABC-123CH` / `ABC-123HD` / `HRV-030A` / `SSIS-123B` / `072214_001`），只测一个 `ch` 用例发现不了 `HD`/`FHD` 被截成 `H`/`F` 这类问题。

26. **归一化只作用于新扫入的记录**。`NormalizeVID` 的调用点只有扫码入库（`ScanHelper` / `ScanTask`）和局域网接口返回（`LanServer`），没有对旧库做批量改写。改完剥离规则后，库里已有的 `ABC-123-CH` 不会自动变干净，需要重新扫描/识别对应目录。若以后要做一次性迁移，注意别在启动流程里全表 `Update`（2362 条记录逐条更新会拖慢启动，且 `Update` 是全行覆盖）。

27. **触摸设备上浏览器补发的 `mousemove` 会抢在单击判定之前，把控件栏"一按就没"**。播放页控件栏自动隐藏后，用户点一下本应唤出控件，实测却是闪一下又消失：

    - 根因：移动浏览器在 tap 之后会补发一次 `mousemove`（还有 `mouseenter`）。旧代码在 `mousemove` 里直接 `showUi()`，于是"显示"发生在 300ms 双击判定之前；等单击定时器到点，读到的当前状态已经是"可见"，于是走了 `hideUi()`。
    - 解法：`pointerdown` 时先快照可见状态（`uiVisibleAtTap = !vc.classList.contains('hidden')`），单击判定用**快照**决定显/隐，不看当前 DOM。这样 `mousemove` 里"悬停即显示"的原有桌面行为可以原样保留，不用为了修这个 bug 把桌面手感改掉。
    - 验收：模拟触摸序列（`pointerdown(pointerType=touch)` → `mousemove` → `click`），`vc` 的类名要交替出现 hidden→visible→hidden→visible；只测鼠标 click 会得到"悬停显示、点击隐藏"的假象，那是对桌面鼠标的正常切换语义，不是同一个 bug。

28. **全屏：页面自带按钮是好的，别为了"修"它改成 CSS 伪全屏**。用户实测：播放页自带的全屏按钮正常，进全屏后自定义控件也在；真正不兼容的是**手机浏览器自带的快捷全屏**（地址栏/系统手势/浏览器菜单那套），那是浏览器层行为，页面改不了。

    - 现状实现就是标准写法：`fullBtn` → `requestFullscreen` / `webkitRequestFullscreen`，都不支持时才退到 `video.webkitEnterFullscreen()`（iOS 兜底）；`fullscreenchange` 只同步按钮图标。
    - **不要**改成"CSS 伪全屏铺满视口"来绕原生全屏：观感会变（没有系统全屏的沉浸感、地址栏处理不一致），而且原来的按钮本来就没坏——2026-11 曾这么改过一次，被用户否掉后回滚。
    - 判断依据：用户说"全屏后控件消失/唤不出"时，先确认他是用页面按钮还是浏览器自带快捷全屏，再决定要不要动代码。

29. **相似推荐：裸 SQL 取回的实体没有演员名，番号和中文标题也不能直接跑二元组**。这几条同时踩中会让推荐"看起来完全随机"：

    - `Video.ActorNames` 是 `[TableField(exist:false)]`，只有 `VideoMapper.SelectVideoByID` 会填。自己拼 SQL 建候选池时必须补一次 `metadata_to_actor join actor_info` 把演员名塞回 `ActorNames`，否则 DTO 里 `Actors` 恒为空、演员维度永远 0 分。
    - 番号类（`MIKR-028`、`MIDV-988`）不能直接算字符二元组：`mikr`/`mida` 共享 `mi`、`06` 这类碎片，会把无关厂牌算出虚高相似度。必须先比字母前缀，前缀相同才按数字接近度细分，前缀不同只给很低分。
    - 中文短片标题整串跑 Dice 会被稀释（同系列「萌宅卡 …」之间也只有 0.1 上下，过不了下限）。正确做法是取开头 2~3 个汉字当**系列标记**，标记相同直接给 0.7+，剩下的部分再按 Dice 细分。
    - 表结构：`metadata_video` 里**没有** `Path`/`FileName` 列，文件名匹配只能写 `metadata.Path`（写错列名 SQL 直接报错，被 catch 吞掉后表现为"永远没有候选"）。
    - 相似度下限（`SIMILAR_MIN_SCORE = 0.09`）必须用**不含随机**的干净分数判断；随机扰动只放在排序阶段对同档候选打散（0.03 一档），否则垃圾内容会靠运气过线，前端就会显示一堆无关推荐。
    - 「同目录」只在**小文件夹**（2~40 个视频）里当同系列信号；番号片常被堆在一个上千文件的大目录里，那里同目录等于随机，必须先 `count(*)` 判断再决定是否采用。

30. **开发版被强杀后可能停在选库页，表现为"启动卡死、端口连不上"**。进程在、窗口标题「欢迎使用 Jvedio」、CPU 很低、`/api/health` 一直拒绝连接：

    - 原因：`WindowConfig.Settings.OpenDataBaseDefault` 为 `false` 时，启动页停在库列表等用户双击；`Window_Main` 没创建，`LanServer`（在 Main 里启动）自然没起。
    - 处理：把 `app_configs.sqlite` 里 `ConfigName='WindowConfig.Settings'` 的 `OpenDataBaseDefault` 置 `true` 再启动，不要误判成崩溃去翻代码。

31. **内置刮削器（豆瓣 / TMDB / Bangumi）的坑几乎全在"候选匹配"，不在接口本身**。三个源的 JSON 都很好解析，真正会写出错误信息的是匹配环节：

    - 豆瓣 `movie.douban.com/j/subject_suggest` **只返回电影类条目**（`type` 全是 `movie`），搜「进击的巨人」只给真人版企划和剧场版，没有 TV 版。所以单集文件（`[01]`、`S01E02`、`第3话`）必须**先问 Bangumi**——`BuiltinCrawlerManager` 用 `query.IsEpisode` 决定顺序，别只改阈值。
    - 文件名没年份时，豆瓣候选里会混进**未上映的真人版**（如 2030 年的「进击的巨人」）。规则：`year > 当前年+1` 扣 0.5 分，`year < 当前年-60` 扣 0.2 分。
    - Bangumi 片库比豆瓣杂得多（有实验短片、OVA、真人版），阈值必须比豆瓣高（0.7 vs 0.5），且文件名带年份时**差两年以上直接排除**：放宽后 `The Matrix (1999)` 会匹配到 1971 年的抽象短片「Matrix I」。
    - Bangumi 详情**必须用 v0 接口** `api.bgm.tv/v0/subjects/{id}`：老接口 `/subject/{id}` 不返回 `infobox` 和 `tags`，导演/动画制作/题材全空。v0 的日期字段是 `date`，老接口是 `air_date`，且存在 `0000-00-00` 占位值，写库前要挡掉。
    - Bangumi 最高频标签常常就是作品名本身，`Genre` 里要过滤掉与标题相同的标签；`Studio` 只取 `动画制作`，取 `製作` 会把整串制作委员会名单写进去。
    - 文件名解析**必须先取年份再摘括号**：`让子弹飞 (2010).mp4` 先摘括号会把年份一起丢掉，标题变成 `让子弹飞 (`。括号正则要同时覆盖 `[]`、`{}`、`()`、`（）`，含中文的保留内部文本（可能是片名），纯 ASCII 的整段丢弃（多为压制组）。

32. **`Video.ParseDictInfo` 以前只认字符串和 `List<string>`，`float` 属性根本写不进去**。刮削器返回的 `Rating` 是 `float`，旧代码只处理 `string` / `List<string>` 两种值：传 float 会被静默跳过（评分永远是 0），传 `"8.3"` 也走不进 `float` 分支。

    - 现在的写法：按 `PropertyType` 分派，`string` 用 `ToString()`，`int` 兼容 `int`/`long`/数字串，`float` 兼容 `float`/`double`/`decimal`/不变文化数字串。
    - 加新字段时注意：**字典键必须等于实体属性名**，映射全靠反射，键名写错不会报错，只会静默不生效。

33. **番号插件"装上了却用不了"有两个独立成因，别只查一个**：

    - **插件目录**：`CrawlerManager.Init` 只扫 `plugins/crawlers/<目录>/`，要求目录里同时有 `main.json` 和 DLL，并把 DLL 复制到 `plugins/crawlers/` 顶层再加载。目录名就是 PluginID 的后半段（`crawlers/bus` → `crawler/bus`）。少 `config.json` 只会打一条 `read plugin config failed` 的警告，插件仍可用；少 `main.json` 则直接跳过。
    - **源记录**：`VideoDownLoader.GetCrawlerServer` 要求 `ServerConfig.CrawlerServers` 里有一条 `PluginID` 匹配、`Enabled`、`Available == 1`、`Url` 非空的记录，否则抛 `CrawlerNotFoundException`（提示像"没装插件"，其实是没配源）。全新安装的数据库里没有 `Servers` 这条配置，所以 `ServerConfig.Read()` 在没有记录时补一条 `crawler/bus` 默认源；用户改过之后会被 `Save()` 覆盖，不会重复。

34. **闭源 `CommonNet.dll` 与全部番号插件都引用 `SuperUtils 1.2.0.0`，而我们重建的 `SuperUtils` 一度是 `0.0.0.0`**：

    - 旧式 csproj（非 SDK 风格）里的 `<AssemblyVersion>1.2.0.0</AssemblyVersion>` **不会**生成程序集特性，产物仍是 `0.0.0.0`。版本号必须写在 `Properties/AssemblyInfo.cs` 里。
    - 目前能跑是因为 `SuperUtils` 没有强名称，CLR 对弱名称程序集按简单名绑定、不校验版本；但这是运气不是设计，改 `AssemblyInfo.cs` 对齐 1.2.0.0 更稳。
    - 同类坑：`SuperUtils` 曾引用 NuGet 的 `Newtonsoft.Json 12.0.3`，而程序分发的是 `Reference\Newtonsoft.Json.dll`（11.0.0.0），又没有 bindingRedirect，于是任何 `SuperUtils.Common.JsonUtils` 调用都抛"程序集清单定义与程序集引用不匹配"，表现为插件 `main.json` 解析失败。给 `SuperUtils` 编译时必须引用**分发的那一份**。

35. **发布包里的 `Data\theme.json` 会和用户数据目录 `data\` 撞在一起**（Windows 路径不区分大小写）：

    - `ThemeLoader.CONFIG_RELATIVE_PATH = @"Data\theme.json"`，是相对**程序目录**的路径；而用户数据在 `data\<用户名>\`。Windows 上 `Data` 与 `data` 是同一个目录，所以主题配置实际落在 `data\theme.json`，和数据库、封面同处一级。
    - 表现：往安装目录覆盖发布包时，`data\` 里会凭空多出 `theme.json`。这不是数据被污染，是资源文件按设计放在那里。**部署校验要把这一项排除**，否则会误判成"用户数据被改动"而中止。
    - 反过来，如果安装目录原本没有 `Data\`（老安装版只拷了二进制），升级后主题自定义才开始生效——这是修复，不是问题。
    - 别为了"干净"去删它，删了主题就回默认值。`data\` 整体备份会把它一起带走，无害。
