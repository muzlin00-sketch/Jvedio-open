# 部署与更新

## 快速决策

| 我要做什么 | 改哪 | 端口 |
|---|---|---|
| 改代码、试功能 | `<dev-dir>`（开发运行目录） | 5201 |
| 更新正式使用的版本 | `<install-dir>`（**验证通过后才动**） | 5200 |

> 本文用两个占位符：`<dev-dir>` 是日常改代码用的运行目录，`<install-dir>` 是正式使用的目录，
> 两者都只是「把构建产物拷进去运行」的普通文件夹，可以按自己的习惯放在任意路径。

**当前形态**：两个独立目录，各自持有 `Jvedio.exe`、`Web\index.html` 和 `data\<用户>\` 数据目录。
端口、数据库、配置文件全部独立，互不影响。这是刻意的——正式目录是日常在用的，不能拿它做试验。

### 操作红线

- 开发目录没跑通全流程前，**不碰正式目录**。
- 覆盖前先确认目标进程已退出，否则文件写不进去（Windows 锁定 exe）。
- 复制文件成功 ≠ 部署成功。要校验哈希 + 探活，见下方「验证」。

## 构建

### 顺序固定，不能跳

```powershell
# 1. 改过 Jvedio.Core 内文件（HttpProtocol.cs 等）→ 必须先编 Core
cd Jvedio-WPF\Jvedio.Core
dotnet build -c Debug

# 2. 再编主程序
$env:TEMP = "<repo>\_buildtools\nugettmp"   # 避免 NuGet 临时目录权限问题
C:\Windows\Microsoft.NET\Framework\v4.0.30319\MSBuild.exe `
  "<repo>\Jvedio-WPF\Jvedio\Jvedio.csproj" /t:Build /p:Configuration=Debug /v:m /nologo
```

跳过第 1 步的后果见 [踩坑约定 #1](踩坑约定.md)。判断方法：看 `Jvedio.Core.dll` 的修改时间是否晚于你改的源码。

### 产物

| 文件 | 来源 |
|---|---|
| `Jvedio.exe` | `Jvedio-WPF\Jvedio\bin\Debug\Jvedio.exe` |
| `Jvedio.Core.dll` | `Jvedio-WPF\Jvedio.Core\bin\Debug\netstandard2.0\Jvedio.Core.dll`（主项目 bin 下也会有一份拷贝） |
| `Web\index.html` | `Jvedio-WPF\Jvedio\Resources\Web\index.html`（内嵌资源，也要单独放到部署目录的 `Web\`） |

## 部署到开发版

```powershell
# 1. 停进程
Get-Process -Name Jvedio | Where-Object { $_.Path -like '*Jvedio-dev*' } | Stop-Process -Force
Start-Sleep -Seconds 4

# 2. 复制产物
Copy-Item <bin>\Jvedio.exe        <dev-dir>\ -Force
Copy-Item <bin>\Jvedio.Core.dll   <dev-dir>\ -Force
Copy-Item <repo>\Jvedio-WPF\Jvedio\Resources\Web\index.html <dev-dir>\Web\ -Force

# 3. 启动（重定向日志便于排错）
Start-Process <dev-dir>\Jvedio.exe -WorkingDirectory <dev-dir> `
  -RedirectStandardOutput <dev-dir>\_stdout.log `
  -RedirectStandardError  <dev-dir>\_stderr.log

# 4. 等服务起来（约 30 秒）
Start-Sleep -Seconds 32
```

## 验证

三层都要过，缺一层就可能"看起来部署成功其实没有"：

```powershell
# 1. 文件一致
Get-FileHash <源> -Algorithm SHA256 ; Get-FileHash <目标> -Algorithm SHA256   # 必须相同

# 2. 服务探活
curl.exe -s -o NUL -w "%{http_code}" http://127.0.0.1:5201/                    # 期望 200

# 3. 行为验证（按改动类型选）
curl.exe -s http://127.0.0.1:5201/api/auth/status                              # 鉴权状态
curl.exe -s -o NUL -w "%{http_code}" -r 0-1023 http://127.0.0.1:5201/stream/4522  # 流接口
```

前端改动还要在移动视口实际点一遍（点击、手势、滚动），不能只看 DOM。

## 配置与数据

| 项 | 位置 |
|---|---|
| 配置 | `data\<用户名>\app_configs.sqlite`，表 `app_configs`，行 `WindowConfig.Settings`（`ConfigValue` 是 JSON） |
| 数据库 | `data\<用户名>\app_datas.sqlite` |
| 日志 | `data\<用户名>\log\<日期>.log` |

**改配置的坑**：直接改数据库里的 JSON 之前先读 [踩坑约定 #2](踩坑约定.md)——
`int` 类型的配置项曾因反射赋值失败而恒定使用默认值。改完要确认日志里读到的值真的变了，
不能只看数据库里写了什么。

**端口改了不生效**同理：确认程序实际读到的是新端口（日志里会打印），而不是数据库里存的值。

## 打便携版发布包

发布包 `release/Jvedio-5.4-portable-win-x64.zip` 用脚本重新打，不要手工 `Compress-Archive` 整个 `bin\Release`：

```powershell
pwsh -NoProfile -File .\build.ps1 -Configuration Release
pwsh -NoProfile -File .\scripts\repack-release.ps1
```

脚本以**现有 zip 的条目清单**为基准，用 `bin\Release` 的同名文件覆盖后重新打包。
这样能保证包里只含运行必需文件（不含 `data\`、`*.pdb`、`*.xml`），换机器打出来的内容也一致。
打完把 zip 提交，并在 GitHub Release 里作为附件上传。

## 打安装包

安装包由便携版 zip 生成，**顺序不能反**：先有 zip 再打 exe，否则装出来的是旧文件。

```powershell
pwsh -NoProfile -File .\scripts\build-installer.ps1
# 输出：release\Jvedio-5.4-setup-win-x64.exe
```

前置：Inno Setup 6（`winget install JRSoftware.InnoSetup`）。脚本找不到 `ISCC.exe` 会直接报错。

安装包行为（改之前先想清楚，用户的数据在里面）：

| 项 | 值 | 原因 |
|---|---|---|
| 安装目录 | `%LOCALAPPDATA%\Programs\Jvedio` | 程序要在自己目录下写 `data\`，装 Program Files 会因权限失败 |
| 权限 | `PrivilegesRequired=lowest` | 全程不需要管理员，也不弹 UAC |
| 卸载 | 只删程序文件，**保留 `data\`** | 影片库和封面在里面，误删代价太大 |
| 快捷方式 | 开始菜单必建，桌面可选（默认不勾） | |
| .NET 检查 | 只提示，不拦截 | 装完再补 .NET 也能用 |

脚本本体在 `scripts/installer/Jvedio.iss`（中文界面，语言包 `ChineseSimplified.isl` 一并放在同目录）。
改完 `.iss` 重新跑一次 `build-installer.ps1` 即可，不需要动主程序。

> 安装包**没有数字签名**，用户首次运行会看到 SmartScreen 提示。要消掉只能买代码签名证书，
> 目前 README 里直接写了「更多信息 → 仍要运行」的过法。
>
> 打包环境注意：安装包是 GUI 程序，**在没有交互桌面的会话里（如纯后台/远程会话）跑不起来**，
> 会卡住或直接退出（退出码 1）。要实测安装流程，得在真实桌面上双击。

## 更新安装版

前置条件：开发版上本次改动全部验证通过，且用户确认现在不用（会重启程序）。

用脚本，不要手工复制：

```powershell
pwsh -NoProfile -File .\scripts\deploy-install.ps1
# 换目录：-InstallDir 'D:\app\Jvedio-5.4'
```

脚本做四件事，缺一件就可能"看起来部署成功其实没有"：

1. **查进程**：`Jvedio` 还在跑就直接退出，不覆盖正在使用的文件。
2. **备份**：把整个安装目录（跳过 `data\`、`Cache\`）拷到同级 `_backup-<目录名>-<时间戳>\`，回滚就靠它。
3. **覆盖**：只覆盖发布包里有的文件，不删除安装目录里多出来的东西——旧 `.bak`、插件中心装的插件、
   老版本遗留的闭源 DLL 都保留。
4. **校验**：10 个关键文件逐一比 SHA256；再比对 `data\` 前后快照，确认用户数据没被动过
   （唯一允许变动的是 `Data\theme.json`，见 [踩坑约定](踩坑约定.md) 第 35 条）。

脚本跑完不会自动启动程序（GUI 需要在交互桌面上起）。手动启动后按上文「验证」第 2、3 层确认：
5200 端口探活、手机端能打开。

回滚：把 `_backup-*` 里的文件覆盖回去即可，`data\` 全程没动过，所以数据一定是对的。

> 安装版目录里存在 `Jvedio.exe.bak`、`Jvedio.Core.dll.bak-*` 等历史备份，不要随手清理。
